# 취소 디버깅 리포트 (Cancellation Debugging Report)

## 1. 버그 증상 (Symptom)
- **현상**: 결제 취소 건이 ERP '입금보고서'에 업로드될 때, 마이너스(-) 부호가 붙지 않고 일반 매출(+100)로 처리되는 문제 발생.
- **결과**: 회계 데이터의 불일치 및 수동 수정 소요 발생.

## 2. 디버깅 과정 (Debugging Process)
1. **로그 분석**: `modules/reader.py`에 상세 디버그 로그를 추가하여 데이터 추출 단계 확인.
2. **현상 파악**: 로그 확인 결과, 추출된 `status`(상태) 값이 실제로는 '취소'임에도 불구하고 프로그램 상에서는 **빈 값(Empty String)**으로 읽히는 것을 발견.
3. **HTML 분석**: ERP 웹 페이지의 요소를 직접 검사(`Inspect`)하여 데이터 컬럼의 ID를 실시간 확인.
4. **불일치 발견**: 기존에 사용하던 `SETL_STAT_NM` 컬럼 ID가 실제 데이터 그리드에서는 존재하지 않거나 변경된 것을 확인.

## 3. 원인 분석 (Root Cause)
- **원인**: `ReaderModule`에서 '상태' 값을 읽어오기 위해 참조하던 DOM Selector의 컬럼 ID가 잘못되어 있었음.
- **상세**: `SETL_STAT_NM` → **존재하지 않는 ID** (이에 따라 `status` 값이 항상 빈 값으로 반환됨).

## 4. 해결책 (Solution)
- **수정 내용**: `modules/reader.py` 내의 상태 컬럼 참조 ID를 실제 유효한 ID인 `SETL_STATUS_TYPE`으로 교체.
- **코드 변화**:
  ```python
  # 변경 전
  status_cells = self.page.locator('span[data-column-id="SETL_STAT_NM"]').all()
  # 변경 후
  status_cells = self.page.locator('span[data-column-id="SETL_STATUS_TYPE"]').all()
  ```

  - 일반 성공 데이터: 2건 정상 처리
- **결과**: [OK] 프로그램이 상태값을 정상 인식하여 취소 건에 대해 정확히 마이너스 처리를 수행함.
