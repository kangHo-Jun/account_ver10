# 취소 디버깅 (Cancellation Debugging)

## 1. 버그 개요 (Bug Overview)
- 결제 내역 중 '취소' 상태의 항목이 ERP에 업로드될 때, 금액 부호(-)가 누락되거나 데이터 형식이 맞지 않아 회계 반영이 부정확하게 일어나는 문제 발생.
- 특히 카드사로부터 넘어오는 데이터의 '상태' 값이나 '금액' 필드에 포함된 특수 공백(전각 공백 등)으로 인해 로직이 오작동함.

## 2. 수정 히스토리 (Modification History)
### Commit: `fecb7e9` (-취소 처리건)
- **상태 값 정규화**: `status.strip()`을 도입하여 앞뒤 공백이 포함된 '취소' 문자열을 정확히 인식하도록 수정.
- **금액 필드 클렌징**: `"".join(row['amount'].split())` 방식을 사용하여 전각 공백(`\u3000`) 및 모든 종류의 화이트스페이스를 제거하고 숫자만 추출하도록 개선.
- **부호 부여 로직**: `status.strip() == '취소'`인 경우 금액이 이미 `-`로 시작하지 않을 때만 마이너스 부호를 추가하도록 가드 로직 반영.

## 3. 현재 남은 문제 (Remaining Issues)
- **미해결 상태**: 위 수정 이후에도 특정 케이스에서 여전히 '취소' 상태 인식이 실패하거나 금액 변환이 누락되는 현상이 발생할 수 있음 (미해결 상태로 명시).
- 실시간 '회계반영' 탭과의 대조 과정에서 취소 건의 승인번호 매칭이 누락되는 케이스 조사 필요.
