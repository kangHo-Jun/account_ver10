# 취소 거래 데이터 처리 디버깅 보고서

## 1. 버그 증상
- **현상:** ERP 업로드 시 취소 거래 건이 금액 부호가 반전되어 업로드됨.
- **예시:** -100원(취소)이 +100원으로 처리되어 중복 결제처럼 인식되는 문제 발생.

## 2. 디버깅 과정
1. **가설 1:** 데이터 추출 시 공백 문제(`status.strip()`)로 인해 조건문이 작동하지 않음.
   - **조치:** `strip()` 적용 후 테스트했으나 동일 증상 발생.
2. **가설 2:** 추출되는 데이터 값 자체가 다름.
   - **조치:** `modules/reader.py`에 상세 디버그 로그 및 Hex 값 출력 코드 추가.
   - **확인 결과:** `status=''` (빈 문자열)로 추출됨을 발견.
3. **가설 3:** ERP HTML 구조 변경 또는 컬럼 ID 오류.
   - **조치:** 브라우저 개발자 도구(F12)를 통해 실제 결제조회 그리드 HTML 검사.
   - **확인 결과:** 기존 코드에서 참조하던 `SETL_STAT_NM` 컬럼이 존재하지 않거나 데이터가 비어 있음을 확인.

## 3. 원인 분석
- **원인:** 데이터 수집 로직에서 참조하는 컬럼 ID가 잘못됨. 
- **내용:** `SETL_STAT_NM` 컬럼은 실제 데이터를 담고 있지 않았으며, 실제 상태 값은 `SETL_STATUS_TYPE` 컬럼에 위치함.

## 4. 해결 방법
- **수정 파일:** `modules/reader.py`
- **수정 내용:** 상태 값 추출 대상을 `SETL_STAT_NM`에서 `SETL_STATUS_TYPE`으로 변경.

## 5. 테스트 결과
- **검증:** 실제 취소 거래 1건을 대상으로 자동화 사이클 실행.
- **결과:** **-100원**으로 정상 인식 및 업로드 완료 확인.
