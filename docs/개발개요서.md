# 결제대행사매출조회 자동화 개발 개요서

## 1. 개발 목적

- 결제대행사(KCP) 매출 데이터를 2시간 주기로 자동 조회 및 입금보고서 업로드

## 2. 대상 사이트

- URL: `loginab.ecount.com` (기존 ERP 동일)
- 메뉴: 결제대행사매출조회 (`prgId=E010207`)
- 결제대행사: `KCP` / `daesan3833` / `ALNU3` / `NHN KCP`

## 3. 조회 순서

1. 페이지 이동 (URL 해시값 변경)
2. 즉시조회 버튼 클릭 (`button#PGSearch`)
3. 팝업에서 조회 클릭
4. 두번째 팝업에서 적용 클릭 (`button#apply`)
5. 결과 데이터 읽기

## 4. 데이터 컬럼 구조

| 컬럼 ID | 컬럼명 | 비고 |
|---|---|---|
| `SETL_DT` | 일자 | |
| `APV_TYPE_CD` | 구분 | 승인/취소 |
| `PGCO_ID` | 결제대행사ID | |
| `PGCO_ALNM` | 결제대행사 | |
| `CUST_NM` | 거래처명 | 빈값 가능 |
| `RCPTR_NM` | 입금처 | 고객명으로 사용 |
| `TAMT` | 금액 | |
| `SETL_MEAN_NM` | 결제수단 | |

## 5. 기존 입금보고서 컬럼 매핑

| 입금보고서 | 기존 | 신규 |
|---|---|---|
| 일자 | `SETL_REQST_DTM` | `SETL_DT` |
| 고객명 | `CUST_NM` | `RCPTR_NM` |
| 금액 | `SETL_AMT` | `TAMT` |
| 카드사 | `ACQUER_NM` | `PGCO_ALNM` |
| 구분 | `SETL_STATUS_TYPE` | `APV_TYPE_CD` |

## 6. 실행 주기

- 2시간 단위 자동 실행

## 7. 기존 시스템과 동일한 패턴 사용

- `reader` → `transformer` → `uploader` 구조 재사용
- `uploaded_records.json` 중복 방지 방식 동일

## 8. 개발 방향 요약

- 조회 대상만 기존 결제내역조회에서 결제대행사매출조회로 변경
- 화면 진입 방식은 기존과 동일하게 URL 해시값 변경 패턴 사용
- 조회 후 읽어오는 컬럼만 신규 화면 기준으로 교체
- 변환 로직은 기존 입금보고서 업로드 형식을 최대한 유지
- 운영 방식은 기존 자동화와 동일하게 주기 실행, 중복 방지, 업로드 흐름을 재사용
